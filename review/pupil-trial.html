Can a pupil learn this independently?

Use a short observed trial to find out. This is a testing guide, not a claim that pupil trials have already taken place.

Choose a manageable sample

Try a Removes sequence with younger pupils and an AEP sequence with older pupils. Include different levels of prior knowledge and pupils who use relevant accessibility features or assistive technology. Follow the school’s normal consent and safeguarding arrangements; use anonymous trial codes in notes.

Suggested Removes sample: How Chatbots Work, Bias In Bias Out, and Fact-Checking. Suggested AEP sample: a shared foundation, Prompt Injection and a prototype testing sprint.

Observe the whole journey

  1. Ask the pupil to choose the course, start the next lesson and explain where they are.
  2. Let them work independently. Record hesitation, help requests and unexpected actions before offering procedural help.
  3. Ask them to complete the rehearsal before opening the examples, then explain one revision.
  4. Ask for their own evidence and a fresh unaided answer. A copied model answer is not evidence of transfer.
  5. Have them save, leave, return and restore a backup on a test browser. Check what they expected to be saved.

Record actual task time and the point where help was needed. Do not infer lesson duration from slide count.

Judge the reasoning

Developing
Names the relevant idea but needs prompting to apply it or support the conclusion.
Secure
Applies the idea to this case, points to evidence and states a relevant limitation.
Ambitious
Transfers the idea to an unfamiliar case, tests an alternative or explains what would change the judgement.

Use the lesson’s own success criteria. Moderate a few samples with another teacher and record disagreements; these prompts are not an automatic grading scheme.

A bias example: “85% means it is fair” misses the group comparison. “The group scores are 95% and 75%, so I need relevant error data before approval” is supported and appropriately limited. A further step proposes a meaningful test and challenge route without claiming the gap proves its cause.

Check access with the pupil’s actual setup

  • Keyboard: open, navigate, answer, reveal guidance and close without a mouse; check visible focus and the return point.
  • Screen reader: test NVDA with Chrome and VoiceOver with Safari where available. Check title announcements, reading order, control names and saved-state messages.
  • Vision and reading: test 200% text enlargement, narrow-screen reflow, contrast, reading font and reduced motion.
  • Mobile and media: test Safari/iOS fullscreen fallback, captions, text alternatives and an interrupted network connection.

Automated checks complement these observations; they do not replace them.

Close the loop

Use this record for each issue: task → observation → consequence → proposed repair → retest result. Avoid recording unnecessary personal information.

After a gap of several days, give a short unfamiliar problem without the lesson open. Compare the pupil’s reasoning with the original task. Use the result to improve explanation, practice and retrieval—not to claim a causal learning effect from a small uncontrolled trial.

Prioritise barriers that prevent participation or mislead understanding. Recheck each repair with pupils before widening use. Keep a dated source review and an owner for sensitive content.
